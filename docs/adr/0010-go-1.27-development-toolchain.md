# ADR 0010 — Go 1.27 development toolchain

- **Status:** accepted
- **Date:** 2026-08-21
- **Deciders:** ARC, OPS, DEV
- **Supersedes:** [ADR 0004](0004-podman-oci-dev-workflow.md) decision
  point 1 only

## Context

ADR 0004 fixed the development image at Go 1.26. Its other decisions remain
active: the image is still a Containerfile built by Podman and Buildah,
orchestrated through the Compose Specification, annotated as OCI, and pinned by
immutable executable identifiers.

The baseline Go-tool layer also persisted `/go/pkg/mod` as a Buildah cache.
An incomplete cached module tree then made later builds fail at valid
`go:embed` declarations. The failure prevented a trustworthy build on which to
validate the mandatory Go 1.27 migration. The approved reconciliation makes the
cache repair and toolchain migration one final repository boundary. The user
required that no Go 1.26.7 intermediate project state be published and
explicitly approved this combined execution boundary.

## Decision

Development uses Go 1.27.0 from exactly:

`docker.io/library/golang:1.27-trixie@sha256:6212da3924947f4b6a939df02ea627c13f338f1a41d6c3fcb0dd9d076eef46c4`

The `go.mod` directive is `go 1.27.0`. A matching `toolchain go1.27.0` line is
omitted because Go defines it implicitly and `go mod tidy` removes the
redundant line. Exact execution remains fail closed through the OCI digest,
`GOTOOLCHAIN=local`, runtime `GOVERSION` parity with `go.mod`, and workflow pin
parity.

The Go-tool build layer persists compiler objects only at the declared
`GOCACHE`. It does not cache `GOMODCACHE` across builds, and it executes the
exact command `go clean -modcache` after the final `go install` so downloaded
module sources do not enter the resulting image layer.

Compose interpolation gives every linked worktree its own project, container
and local image tag. Its suffix combines a sanitized lowercase basename,
bounded to 48 characters, with the first 12 hexadecimal characters of SHA-256
over the canonical top-level checkout path returned by Git. Thus identity is
stable from subdirectories, equal base names at different full paths remain
distinct, and branch leaves cannot create unbounded object names. The primary
checkout retains the historical empty suffix.

Routine `task up` remains non-destructive. The explicit `task recreate` first
builds, then verifies that the exact-name container has both the expected
Compose project label and a canonical `/app` bind source equal to the current
worktree before removing it. A missing or mismatched ownership signal stops
before removal. This follows the
[Compose interpolation contract](https://github.com/compose-spec/compose-spec/blob/main/12-interpolation.md),
which applies `${VARIABLE:-default}` to YAML values before Compose uses them.

## Consequences

- Builds cannot reuse incomplete module-source trees or retain module and
  compiler cache residue in the final OCI filesystem.
- Concurrent worktrees cannot race through a shared Compose project or local
  development-image tag.
- A rebuilt image does not silently make an existing container current;
  container-backed gates report `task recreate`, whose destructive scope is
  explicit and ownership checked.
- Go version drift is detected across `go.mod`, the development image, the
  running container and Go-facing workflows.
- ADR 0004 decision points 2 through 6 remain unchanged.
